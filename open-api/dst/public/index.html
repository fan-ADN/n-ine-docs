ミニアプリに紐づくジャンル一覧を取得

指定したミニアプリIDに紐づくジャンルグループとジャンルの階層構造を取得します。

リマインダーの通知がONの利用者に配信する場合: 利用タグ（usageTagId）でミニアプリの利用者に絞り込み、対象ジャンルの通知OFFタグ（tagId）で除外します。 初期値のまま通知がONの利用者も対象です。初期設定が必要なミニアプリでは、初期設定を完了した利用者、 または既存の通知設定により初期設定が不要な利用者が対象となり、初期設定が必要なまま未完了の利用者は対象外です。 初期設定が不要なミニアプリでは、起動した利用者が対象です。

利用開始前に、利用タグの設定と既存利用者の移行が完了していることをサービス担当者へ確認してください。 usageTagId が返されるだけでは移行完了を判断できません。 usageTagId または対象ジャンルの tagId が null の場合、この方法での配信は行わず、サービス担当者へ確認してください。

対象ジャンルを1件指定する場合、POST /multicasts に次の配信条件を設定します。 CRMアカウントID、メッセージ、配信予約日時などは、同APIの仕様に従って指定してください。

  • isBroadcast: false
  • includeTagIds: usageTagId のみを含む配列
  • excludeTagIds: 対象ジャンルの tagId のみを含む配列
  • targetingSettings.includeTargetType: TAGS
  • targetingSettings.includeTagConditionType: AND
  • targetingSettings.excludeTagConditionType: OR

利用タグはサービスが自動的に付与します。管理画面・一括操作・APIで利用者に付け外ししたり、タグ自体を削除したりしないでください。 配信対象の絞り込み専用のため、タグ付与をきっかけにするステップ配信やリッチメニューの切り替え条件には使用しないでください。

Authorizations:
ApiKeyAuth
path Parameters
miniappId
required
string
Example: 01HQZX1234567890ABCDEFGHIJ

計測リンクを一括作成

計測リンク（tracking links）を一括作成します（1リクエストあたり最大100件）。

各リンクはトランザクションで作成され、デフォルトのリダイレクト条件（priority=0）も自動生成されます。 リンクごとに独立して作成されるため、1件の失敗は他の件に影響しません（レスポンスに件別の成否が返ります）。

一意ルール（違反時は400で、messageに重複箇所が返ります）:

  • analyticsTags: eventNameとtagIdの組み合わせはanalyticsTags配列内で一意
  • clickTags: tagIdはclickTags配列内で一意
  • defaultParameters: sourceParameterはdefaultParameters配列内で一意
  • redirectConditions: priorityはredirectConditions配列内で一意（1以上・昇順に評価）
  • redirectConditions[].tags: tagIdは同一redirectConditions要素のtags配列内で一意（要素をまたぐ重複は可）
  • redirectConditions[].parameters: sourceParameterは同一redirectConditions要素のparameters配列内で一意（要素をまたぐ重複は可）

応答メッセージを作成

応答メッセージを1件作成し、作成した応答メッセージのIDを返します。返ったIDはそのまま編集（PATCH /auto-responses/{autoResponseId}）に使えます。

入力チェック（管理画面・CSV一括入稿と同じです）:

  • trigger.keywordsとtrigger.lineUserPostbackActionTagRuleIdsの少なくとも一方に1件以上必要です
  • キーワードは最大10個で、重複はできません
  • 応答設定（messageGroups）は1〜100個、1つの応答設定のメッセージはアンケートを含めて1〜5個、タグは最大50個です
  • タグはタグIDまたはタグ名で指定します。26文字の英数字はまずタグIDとして引き、見つからなければタグ名として引きます。それ以外の文字列はタグ名として引きます。存在しないタグは400になり、タグが自動作成されることはありません
  • 指定したCRMアカウントに属さないタグ・アンケート・ポストバック条件のIDは400になります
  • メッセージ種別と中身の組み合わせが合わないものは400になります。SURVEYはsurveyIdだけを、それ以外はmessageJsonだけを指定し、messageJson.typeを大文字にした値がmessageTypeと一致する必要があります（例: TEXTにはtype: "text"）
  • messageJsonはLINE Messaging APIのメッセージ形式チェックにかけ、受け付けられない形式は400になります
  • LINE連携情報（Messaging APIのチャネル）が未登録のCRMアカウントは指定できません（400 LINE account configuration not found）

再送について: このAPIは冪等ではありません。通信が途中で切れたリクエストを再送すると、同じ内容の応答メッセージが二重に作成されることがあります。再送する前に一覧取得で作成済みでないかを確認してください。

応答メッセージを編集

応答メッセージを編集します。変えたい項目だけを指定してください。省略した項目は今の値のまま残ります。

  • intervalSeconds / availableFrom / availableUntilは、nullを指定すると設定を消します
  • trigger.keywordsとtrigger.lineUserPostbackActionTagRuleIdsは別々に置き換えられます（一方だけ指定すると、もう一方は今の値のまま残ります）
  • messageGroupsを指定すると、応答設定を丸ごと置き換えます。指定しなかった既存の応答設定は消えるため、一部だけ直すときは詳細取得で今の内容を取得し、手を加えてから全体を指定してください
  • messageGroupsを省略すると、既存の応答設定はそのまま残ります
  • 応答メッセージが属するCRMアカウントは変更できません（crmAccountIdを指定しても無視します）

入力チェックは作成（POST /auto-responses）と同じです。編集後にtriggerのキーワードとポストバック条件の両方が空になる場合も400になります。 messageGroupsを指定したときは、送っていない項目も含めた編集後の内容全体をチェックします。LINE連携情報が未登録のCRMアカウントでは、messageGroupsを指定すると400 LINE account configuration not foundになります。
